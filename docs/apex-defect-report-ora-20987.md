# Defect report — Create App with AI generates dashboard charts that fail at runtime (ORA-20987)

**Reported by:** Rick Houlihan · **Found:** 2026-08-30, validating LiveLabs workshop WMS 12192
**Status:** ready to send — not yet sent

---

## Summary

Applications generated by **Create App Using Generative AI** with a **Dashboard** page produce chart
regions that fail at runtime with `ORA-20987` and render "No data to display". The failure is in the
metadata the wizard writes; the user has done nothing wrong, and the offending attribute is **not
visible anywhere in Page Designer**.

## Environment

| | |
|---|---|
| APEX | **26.1.4** |
| Database | Oracle Autonomous AI Database, version **26ai**, Always Free |
| ORDS | Autonomous-managed |
| Region / tenancy | `us-phoenix-1`, customer-owned tenancy |
| Generative AI service | OCI Generative AI, `us-chicago-1`, `cohere.command-a-03-2025` |
| Workspace schema | `WKSP_HELPDESK` |

## Steps to reproduce

1. Create three tables; the relevant one is `TICKETS` with an identity `ID` primary key plus
   `SUBJECT, DESCRIPTION, STATUS, PRIORITY, CATEGORY, CREATED_ON, ASSIGNED_TO, REPLY`. Seed 50 rows.
2. **App Builder > Create > Create App Using Generative AI**.
3. Prompt (abbreviated): *"Create an application named Horizon Help Desk using my existing TICKETS,
   KB_ARTICLES and TEAM_MEMBERS tables. 1. Dashboard - make this the home page. Include a chart of ticket
   counts by STATUS and a chart of ticket counts by CATEGORY. 2. Tickets - an Interactive Report on the
   TICKETS table, with an editable form to edit a single ticket. 3. Knowledge Base - a report on the
   KB_ARTICLES table."*
4. Accept the blueprint, click **Create Application** in the wizard.
5. **Run Application** and sign in.

## Actual result

The Dashboard shows both chart regions empty with "No data to display", and:

```
Ajax call returned server error ORA-20987: APEX - Column "ID" specified for attribute ""
has not been found in data source! for Tickets by Category.
```

The error alternates between the two chart region names across reloads.

## Expected result

The generated charts render the aggregated data.

## Diagnosis

Each generated chart series has:

- **Source Type**: `Table / View`, Table `TICKETS`, no Where clause
- **Column Mapping**: `Label` = `STATUS` (or `CATEGORY`), **`Value Aggregation` = `Count`**, and **no
  `Value` column** — the `Value` property is not offered while an aggregation is set

Changing **Source Type** to `SQL Query` reveals the query the wizard generated for the series:

```
select ID,
       SUBJECT,
       DESCRIPTION,
       STATUS,
       PRIORITY,
       CATEGORY,
       CREATED_ON,
       ASSIGNED_TO,
       REPLY
from TICKETS
```

The series projects **all columns, including `ID`**, and then applies the `Count` aggregation. After the
implied `group by`, `ID` is no longer in the result set, so the retained reference to it cannot resolve.

Two things make this hard for a user to diagnose:

1. The failing attribute is reported as `""` — a blank attribute name.
2. That attribute is **not exposed in the Page Designer property editor**, on either the series or the
   region. There is nothing for the user to correct in the UI.

Re-saving the page does **not** rewrite the metadata; the error persists.

## Workaround (verified)

Per chart series: set **Source > Type** to `SQL Query`, supply an explicit aggregate query, and map the
columns directly.

```
select status as label, count(*) as value from tickets group by status order by 1
```

Then **Column Mapping**: `Label` = `LABEL`, `Value` = `VALUE`. `Value Aggregation` correctly disappears.
Save and reload — both charts render.

## Impact

- Hits **every** app generated with a Dashboard page over a table with a primary key, which is the
  common case.
- Lands on the **first screen the user sees** after generating their application.
- For LiveLabs workshop WMS 12192 this is the moment the lab says *"a real web application ... from one
  reviewed prompt"*, so the credibility cost is disproportionate to the size of the bug.

## Suggested fix

When a chart series uses `Table / View` with a `Value Aggregation`, the generated data source should
project only the grouping column and the aggregated expression — or the wizard should emit an explicit
`SQL Query` source, as the workaround does.
